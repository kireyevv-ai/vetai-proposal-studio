# VETAI Proposal Studio

Конструктор коммерческих предложений для сервисного бизнеса. Менеджер заполняет
короткий бриф о клиенте и задаче — система готовит структурированный черновик
текста КП, автоматически подставляет цены из прайса и сроки из брифа, помогает
отредактировать документ и выгрузить его в PDF. Все созданные предложения
и их версии сохраняются в истории и доступны для просмотра в любой момент.

> **Принципиальная особенность.** Языковая модель генерирует только текст
> предложения. Цены рассчитываются программой по прайсу услуг, сроки берутся
> из брифа; разделы, для которых не хватает доверенных данных, не генерируются
> и помечаются как «Требует уточнения». Перед экспортом в PDF документ
> проходит защитную проверку: расхождения коммерческих условий блокируют
> выгрузку.

---

## Для кого предназначен

Продукт рассчитан на сервисные компании, которые регулярно готовят
коммерческие предложения вручную: ремонт и обслуживание техники, клининг,
монтаж и инженерные работы, IT- и бытовые сервисы, небольшие производственные
и подрядные организации.

Типовой круг участников работы с КП:

| Участник | Работа в продукте |
|----------|-------------------|
| Менеджер по продажам | Заполняет бриф, редактирует текст, выгружает PDF |
| Руководитель или владелец | Задаёт прайс услуг и шаблон структуры КП |

Текущая версия предназначена для локального использования. Многопользовательский
доступ и разграничение прав пока не реализованы (см. «Текущие ограничения»).

## Бизнес-задачи

- **Единый стандарт предложений.** Все КП оформляются по одному шаблону
  с одинаковой структурой разделов, независимо от того, кто их готовит.
- **Быстрый первый черновик.** Рутинное описание услуг и формулировки
  пишутся автоматически по брифу; менеджер работает с готовым текстом,
  а не с пустым документом.
- **Точность коммерческих условий.** Цены берутся из действующего прайса,
  сроки — из брифа; перед экспортом документ проходит проверку, которая
  блокирует выгрузку при расхождении условий или отсутствии цен.
- **Контроль изменений.** Каждая генерация и каждое сохранение правок
  создаёт неизменяемую версию; можно посмотреть, что и когда менялось,
  и открыть любой сохранённый вариант в редакторе или предпросмотре.
- **Готовый документ для клиента.** Итоговый файл выгружается в PDF
  без служебных заметок и вспомогательных элементов.

## Основные возможности

- **Бриф** — пять обязательных полей (клиент, задача, услуги, сроки, бюджет)
  с валидацией; генерация недоступна, пока поля не заполнены. Услуги
  выбираются из прайса.
- **Генерация черновика** через GigaChat API по настроенному шаблону КП.
- **Прайс услуг и шаблон КП** на экране «Настройки»; цены хранятся
  в копейках (расчёты без округления), шаблон задаёт обязательные разделы.
- **Импорт прайса из Excel** (`.xlsx`) с предпросмотром и подтверждением.
- **Программная сборка коммерческого блока** — цены и сроки вставляются
  в текст из прайса и брифа по кнопке «Пересчитать».
- **Редактирование и версии** — изменения сохраняются отдельными версиями
  (`generated`, `edited`, `exported`); прошлые версии не изменяются.
- **Защитная проверка перед экспортом** — структурная сверка блокирует
  выгрузку при критичных расхождениях; эвристические предупреждения
  (подозрительные числа и формулировки) выводятся без блокировки.
- **Экспорт PDF** выбранной версии.
- **История КП** — список предложений и версий с датами и статусами.
- **Обработка ошибок AI** — понятные сообщения о таймауте, лимите, отказе
  авторизации и некорректном ответе; бриф сохраняется до вызова API
  и при сбое не теряется.
- **Обезличенные логи генерации** — без персональных данных и без ключей.
- **Режим mock** — локальная генерация без обращения к внешнему API
  (для демонстрации и разработки без ключа).

## Как работает

1. **Настройки.** Заполняется прайс услуг (вручную или импортом из Excel)
   и шаблон КП с обязательными разделами.
2. **Бриф.** Менеджер указывает клиента, задачу, нужные услуги, сроки
   и бюджет; незаполненный бриф генерацию не запускает.
3. **Генерация.** Текст черновика создаёт модель, коммерческие условия
   подставляются программой. Создаётся первая версия КП.
4. **Редактирование.** Текст правится вручную; коммерческий блок при
   необходимости пересчитывается из прайса и брифа. Каждое сохранение —
   новая версия.
5. **Проверка.** Перед экспортом выполняется сверка структуры и условий;
   критичные проблемы блокируют выгрузку, остальные выводятся
   предупреждениями.
6. **PDF и архив.** Выбранная версия экспортируется в PDF и помечается
   как выгруженная; все КП и версии остаются в истории.

## Установка и запуск

Требования: Python 3.10+ и pip; Windows, macOS или Linux. Интернет нужен
только для работы с GigaChat API — режим mock и тесты работают офлайн.

```bash
python -m venv .venv

# Windows (PowerShell):
.venv\Scripts\Activate.ps1
# macOS / Linux:
source .venv/bin/activate

pip install -r requirements.txt -r requirements-dev.txt
```

Создайте файл `.env` из шаблона:

```bash
# Linux / macOS:
cp .env.example .env

# Windows (PowerShell):
Copy-Item .env.example .env
```

Заполните `.env` своими значениями (см. следующий раздел). Запуск:

```bash
streamlit run app.py
```

Приложение откроется в браузере (порт по умолчанию — 8501). Навигация
в боковой панели: **Бриф**, **Черновик**, **Предпросмотр и PDF**,
**История КП**, **Настройки**.

База данных создаётся автоматически при первом запуске: каталог `data/`,
схема и безопасные миграции применяются без ручных шагов. Путь к базе
задаётся переменной `VETAI_DB_PATH` (по умолчанию
`data/vetai_proposal_studio.db`); файл базы в репозиторий не попадает.

Проверка установки (необязательно):

```bash
pytest
```

Набор включает защитные сценарии: цены, структуру КП, ошибки API,
версии и PDF. Реальный API в тестах не вызывается.

## Настройка GigaChat API

**Получение ключа.** Ключ получается в кабинете разработчика Sber
(devices.sber.ru / developers.sber.ru): создайте проект, запросите
авторизационные данные. Кабинет выдаёт Client ID и Client Secret, а также
готовый ключ авторизации — `base64("ClientID:ClientSecret")`. Если выданы
только Client ID и Client Secret, соберите ключ самостоятельно:

```powershell
# Windows PowerShell:
[Convert]::ToBase64String([Text.Encoding]::UTF8.GetBytes("ClientID:ClientSecret"))
```

**Переменные окружения** (файл `.env`, в репозиторий не коммитится):

| Переменная | Назначение | По умолчанию |
|------------|------------|--------------|
| `AI_PROVIDER` | `gigachat` — работа через GigaChat; `mock` — локальный режим без сети | `gigachat` |
| `GIGACHAT_AUTH_KEY` | Ключ авторизации (base64 от `ClientID:ClientSecret`) | — |
| `GIGACHAT_SCOPE` | Область доступа: `GIGACHAT_API_PERS`, `GIGACHAT_API_B2B` или `GIGACHAT_API_CORP` | `GIGACHAT_API_PERS` |
| `GIGACHAT_MODEL` | Имя модели | `GigaChat` |
| `GIGACHAT_BASE_URL` | Базовый URL API | значение из приложения |
| `GIGACHAT_AUTH_URL` | URL авторизации OAuth | значение из приложения |
| `GIGACHAT_CA_BUNDLE_FILE` | Путь к корневому сертификату Минцифры (необязательно) | не задано |
| `AI_TIMEOUT_SECONDS` | Таймаут обращения к API, сек | `60` |
| `VETAI_DB_PATH` | Путь к файлу SQLite (необязательно) | `data/vetai_proposal_studio.db` |

Scope должен соответствовать типу владельца ключа (физлицо или юрлицо).
Подробные комментарии по получению ключа — в `.env.example`.

**Безопасное хранение ключа.** `GIGACHAT_AUTH_KEY` читается только из
переменных окружения. Ключ не хранится в коде, не пишется в логи и не
попадает в базу, PDF или репозиторий; файл `.env` добавлен в `.gitignore`.
Не встраивайте ключ в скрипты запуска и не передавайте его другим людям
в открытом виде.

**Проверка TLS** включена всегда. При необходимости можно указать доверенный
корневой сертификат Минцифры (`GIGACHAT_CA_BUNDLE_FILE`); отключить
проверку нельзя.

**Режим mock.** Задайте `AI_PROVIDER=mock` — приложение будет генерировать
черновики локально, без обращения к внешнему API. Полезно для демонстрации
продукта и разработки, если ключа ещё нет.

## Безопасность коммерческих условий и обработка ошибок

- **Коммерческие условия не доверяются модели.** Цены собираются кодом
  из прайса (целые копейки, точная арифметика), сроки — из брифа
  в формате «число + единица измерения». Разделы цен и сроков модели
  не передаются.
- **Отсутствующие данные не заменяются выдумками.** Если услуга из брифа
  не найдена в прайсе или отменена, цена не подставляется, итог
  не рассчитывается, выводится предупреждение.
- **Проверка перед экспортом.** Структурная сверка (наличие разделов
  шаблона, цен и сроков в зафиксированном снимке условий) блокирует
  выгрузку PDF; эвристические предупреждения о подозрительных числах
  и формулировках не блокируют, но выводятся перед экспортом.
- **Снимок условий.** Каждая версия КП хранит цены и сроки, действовавшие
  на момент её создания, — история условий не искажается при изменении
  прайса.
- **Ошибки API.** Таймаут, превышение лимита, сетевая ошибка, отказ
  авторизации, пустой или некорректный ответ модели показываются
  понятным сообщением. Бриф сохраняется до вызова API, поэтому при сбое
  введённые данные не теряются и генерацию можно повторить.
- **Логи.** Записывается факт обращения (провайдер, статус, длительность)
  без персональных данных и без ключей.
- **Человеческая проверка обязательна.** Автоматические проверки снижают
  риск ошибки, но не гарантируют обнаружение всех неточностей; эвристика
  может давать ложные срабатывания и пропуски. Перед отправкой клиенту
  финальный текст вычитывается вручную.

## Текущие ограничения

- **Локальное развёртывание.** Приложение работает на одном компьютере
  в локальной сети; веб-хостинга, облачной версии и удалённого доступа нет.
- **Однопользовательское хранилище.** Данные хранятся в одном локальном
  файле SQLite; совместная одновременная работа нескольких пользователей
  и синхронизация между устройствами не предусмотрены.
- **Нет разграничения доступа.** Авторизации и прав ролей нет: любой,
  у кого есть доступ к компьютеру, работает со всеми разделами, включая
  прайс и настройки.
- **Один активный прайс и один шаблон КП** на базу данных.
- **Особенности Streamlit.** Состояние интерфейса живёт в памяти процесса:
  перезапуск приложения сбрасывает экраны (данные в базе сохраняются);
  отдельного фронтенда и мобильного приложения нет.
- **Проверки не заменяют экспертизу.** Защитные проверки и эвристика
  работают по заданным правилам и не являются юридической или
  финансовой экспертизой документа.

## Направления развития

- Демонстрационный набор обезличенных данных для быстрого старта.
- Профиль компании (реквизиты, описание, контакты) для автоматического
  раздела «О компании» в КП.
- Брендинг PDF: логотип, фирменные цвета и подпись отправителя.
- Развёртывание на сервере компании для совместной работы отдела продаж.
- Разграничение доступа и роли при переходе к многопользовательскому
  режиму.
