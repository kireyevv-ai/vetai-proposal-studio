# VETAI Proposal Studio

Учебный AI-конструктор коммерческих предложений для сервисной компании.
Сценарий: бриф → проверка обязательных полей → генерация черновика через AI →
ручное редактирование → экспорт PDF → история КП.

> **Текущий этап:** каркас приложения, база данных SQLite, форма брифа,
> настройки (прайс услуг и шаблон КП) и **генерация черновика КП через
> GigaChat API**. Коммерческие разделы (стоимость, сроки) формируются
> программно из прайса и брифа. Ручной редактор, экспорт PDF и история КП ещё
> **не реализованы** — соответствующие экраны явно сообщают о своём статусе.
> Используйте только обезличенные учебные данные.

## Требования

- Python 3.10+
- pip

## Установка

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt -r requirements-dev.txt
```

Скопируйте `.env.example` в `.env` и при необходимости заполните значения.
Реальные API-ключи в репозиторий не добавляются.

### AI-провайдер

- **GigaChat (по умолчанию).** Укажите `GIGACHAT_AUTH_KEY` (и при необходимости
  `GIGACHAT_SCOPE`, `GIGACHAT_MODEL`, `GIGACHAT_BASE_URL`,
  `GIGACHAT_CA_BUNDLE_FILE`). Авторизация — официальный OAuth: ключ читается
  только из переменных окружения. Проверка TLS **включена всегда**; при
  необходимости можно лишь указать доверенный корневой сертификат Минцифры
  (`GIGACHAT_CA_BUNDLE_FILE`), но не отключить проверку.
- **Демо без ключа.** Задайте `AI_PROVIDER=mock` — включится безопасный
  локальный провайдер: сценарий «бриф → черновик» работает без обращения к
  внешнему API (используется в тестах и для демонстрации).

## Запуск

```bash
streamlit run app.py
```

Приложение откроется в браузере. Навигация в боковой панели: четыре экрана ТЗ —
**Бриф**, **Черновик**, **Предпросмотр и PDF**, **История КП** — и служебный
экран **Настройки** (прайс услуг и шаблон КП).

Порядок работы: в разделе «Настройки» добавьте услуги и цены, затем заполните
бриф — услуги в нём выбираются из прайса. Кнопка **«Сгенерировать КП»** на
экране «Бриф» сохраняет бриф и открывает экран «Черновик» с результатом.
Коммерческие разделы (стоимость, сроки) заполняются программой из прайса и
брифа, а не моделью.

## Данные и приватность

- Брифы хранятся локально в SQLite (по умолчанию `data/vetai_proposal_studio.db`).
- Прайс и шаблон КП хранятся в тех же SQLite-таблицах; **цены — в копейках**
  (целыми числами, без float) и подставляются в КП программно, а не моделью.
- Услуги в брифе выбираются из активных позиций прайса (раздел «Настройки»);
  архивирование или удаление позиции не изменяет уже сохранённые брифы.
- Результат генерации хранится в `proposals` / `proposal_versions`
  (`status=generated`) с `commercial_snapshot` — зафиксированными ценами и
  сроками версии.
- Логи промптов/ответов (`generation_logs`) записываются **обезличенными**:
  имя клиента, email, телефоны и секреты маскируются; API-ключ в логи не
  попадает.
- Секреты хранятся только в переменных окружения (`.env`), который исключён из Git.
- Логи не должны содержать персональных данных.
