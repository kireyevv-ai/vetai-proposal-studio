# VETAI · Конструктор КП (VETAI Proposal Studio)

Учебный AI-конструктор коммерческих предложений (КП) для сервисной компании.
Сценарий: бриф → проверка обязательных полей → генерация черновика через AI →
ручное редактирование → защитная проверка → экспорт PDF → история КП.

Ключевая идея: ИИ ускоряет написание текста, но коммерческие условия (цены, сроки,
гарантии) формируются **кодом из доверенных данных**, а не моделью.

> Учебный проект курса OpenCode. Приложение работает **только локально** —
> публикация в интернет не выполнялась. Используйте только обезличенные
> учебные данные (REQ-38).

---

## Для кого предназначено

Роли описаны в ТЗ школы. В MVP это **логические роли без системы авторизации**
(OQ-04: локальный учебный MVP без входа в систему):

| Роль | Что делает |
|------|------------|
| **Менеджер** | Заполняет бриф, редактирует текст КП, выгружает PDF |
| **Руководитель** | Задаёт прайс услуг и шаблон структуры КП (экран «Настройки») |

## Реализованные функции

### Обязательный функционал (по ТЗ школы)

- **Экран «Бриф»** — пять обязательных полей (клиент, задача, услуги, сроки,
  бюджет), валидация и блокировка генерации при незаполненных полях
  (REQ-01..REQ-05). Услуги выбираются из прайса.
- **Генерация черновика** через **GigaChat API** по утверждённому шаблону;
  провайдеро-независимый слой интеграции (REQ-06..REQ-09, REQ-08).
- **Программная подстановка коммерческих условий**: цены — из прайса, сроки —
  из брифа; модель не формирует цен и сроков; разделы без доверенных данных
  не генерируются и помечаются «Требует уточнения» (REQ-10..REQ-13, REQ-45).
- **Ручное редактирование** текста на экране «Черновик»; коммерческий блок
  пересчитывается кнопкой из доверенных данных (REQ-15..REQ-17).
- **Защитная проверка перед экспортом**: структурная сверка со снимком
  коммерческих условий (уровень critical — блокирует экспорт) и эвристика
  «подозрительных» фраз (warnings — не блокирует) (REQ-14, OQ-07).
- **Экспорт PDF** (ReportLab) из выбранной версии КП; в PDF не попадают
  служебные заметки, ключи и персональные данные (REQ-18..REQ-21, REQ-35).
- **История КП** — список КП и версий с датами и статусами; прошлые версии
  неизменяемы (REQ-22..REQ-25).
- **Экран «Настройки»** — прайс услуг (цены хранятся в копейках) и шаблон КП
  с обязательными разделами (REQ-26..REQ-29; решение OQ-02).
- **Обработка ошибок AI** — понятные сообщения, бриф сохраняется до вызова
  API и при сбое не теряется (REQ-33..REQ-36).
- **Логи генерации** записываются обезличенно: без PII и без секретов
  (REQ-30..REQ-32).
- **SQLite-хранилище** с безопасным созданием/миграцией схемы (REQ-39).

### Дополнительные функции (согласованные сверх ТЗ)

- **Импорт прайса из Excel** (`.xlsx`, E-06) — дополнительная возможность,
  не входящая в ТЗ школы: раздел «Настройки → Услуги и цены», двухшаговый
  (предпросмотр → подтверждение), транзакционный, без реактивации архива.
- Провайдеро-независимый AI-адаптер с mock-режимом (E-01) и снимок
  коммерческих условий `commercial_snapshot` в версии КП (E-02) —
  реализованные технические приёмы.

## Настройка переменных окружения (.env)


Заполните `.env` локальными значениями. В репозиторий ключи не добавляются:
`.env` в `.gitignore`, а `.env.example` содержит только пустые/демонстрационные
значения. Примеры ниже — безопасные заполнители, вставляйте свои значения
только локально.

| Переменная | Назначение | Значение по умолчанию |
|------------|------------|------------------------|
| `AI_PROVIDER` | `gigachat` — реальный режим; `mock` — локальный без сети | `gigachat` |
| `GIGACHAT_AUTH_KEY` | Ключ авторизации (base64 от `ClientID:ClientSecret`); читается только из окружения | *(пусто)* |

| `GIGACHAT_MODEL` | Имя модели | `GigaChat` |
| `GIGACHAT_BASE_URL` | Базовый URL API | URL по умолчанию из `vetai/config.py` |
| `GIGACHAT_AUTH_URL` | URL авторизации OAuth | URL по умолчанию из `vetai/config.py` |
| `GIGACHAT_CA_BUNDLE_FILE` | Путь к корневому сертификату Минцифры (необязательно) | не задано |
| `AI_TIMEOUT_SECONDS` | Таймаут обращения к провайдеру, сек | `60` |

Подробная инструкция по получению ключа — в комментариях к `.env.example`.

## Настройка GigaChat API и безопасный режим mock

- **GigaChat (режим по умолчанию).** Ключ получается в кабинете разработчика
  Sber (developers.sber.ru): Client ID + Client Secret, собранные в
  `base64("ClientID:ClientSecret")` — готовый «ключ авторизации».
  `GIGACHAT_AUTH_KEY` хранится **только** в переменных окружения (REQ-33) и
  никогда не попадает в код, логи и репозиторий (REQ-34).
- **Проверка TLS включена всегда.** При необходимости можно лишь указать
  доверенный корневой сертификат Минцифры (`GIGACHAT_CA_BUNDLE_FILE`),
  отключить проверку нельзя.
- **Безопасный режим без ключа.** Задайте `AI_PROVIDER=mock` — включится
  локальный провайдер: сценарий «бриф → черновик» работает без обращений к
  внешнему API. Используется в тестах и для демонстрации без ключа.

## Инициализация SQLite

Ручные шаги не нужны: при каждом запуске `app.py` вызывается
`init_database()` — создаётся каталог `data/`, применяется схема
`vetai/schema.sql` и безопасные миграции (например, перевод цен в копейки).
Путь к базе переопределяется переменной `VETAI_DB_PATH`. Файл базы входит в
`.gitignore` и в Git не коммитится.

## Основной пользовательский сценарий

1. **«Настройки»** — руководитель заполняет прайс услуг (цены вводятся в
   рублях, хранятся в копейках) и шаблон КП с обязательными разделами.
   Дополнительно доступен импорт прайса из Excel.
2. **«Бриф»** — менеджер заполняет пять обязательных полей; пока они не
   заполнены, генерация заблокирована. Можно сохранить бриф кнопкой
   «Сохранить бриф».
3. **«Сгенерировать КП»** — бриф сохраняется, затем вызывается провайдер.
   При успехе создаётся версия `generated` со снимком коммерческих условий
   (`commercial_snapshot`) и открывается экран «Черновик».
4. **«Черновик»** — ручное редактирование текста. «Сохранить изменения»
   создаёт версию `edited`; «Пересчитать стоимость и сроки» заново собирает
   коммерческий блок из прайса и брифа.
5. **«История КП»** — список КП и версий с датами и статусами
   (`generated` / `edited` / `exported`); выбранная версия открывается
   в предпросмотре.
6. **«Предпросмотр и PDF»** — показ выбранной (или последней) версии,
   защитная проверка перед экспортом, кнопка «Скачать PDF»; после экспорта
   версия помечается `exported`.

## Обработка ошибок API

Все ошибки провайдера преобразуются в доменные исключения
(`vetai/ai/errors.py`) и показываются пользователю понятным сообщением:
таймаут, превышение лимита, сетевая ошибка, отказ авторизации (неверный
ключ/scope), пустой ответ, некорректный JSON, ошибка структуры ответа.

- **Бриф сохраняется до вызова провайдера** — при любом сбое данные не
  теряются (REQ-36), пользователь может повторить генерацию.
- Ответ проверяется на соответствие шаблону (REQ-13); неполный/некорректный
  ответ не проходит дальше как готовый черновик.
- Лог фиксирует факт обращения (провайдер, статус, длительность) без
  персональных данных и без ключа (REQ-30..REQ-32).

## Как формируются стоимость и сроки

- Цены берутся **кодом** из прайса (`vetai/services/commercial.py`);
  хранение — целые копейки, расчёты через `Decimal` (без float).
- Сроки берутся из брифа в формате «число + единица измерения»
  (нормализация — `vetai/services/deadline_fix.py`).
- Разделы `pricing`/`deadlines` модели **не передаются** — модель не может
  придумать цену или срок (REQ-10, REQ-12).
- Услуга из брифа отсутствует в прайсе или архивная → цена не подставляется,
  итог не рассчитывается, выводится предупреждение; цена не выдумывается.
- Фиксация: каждая версия КП хранит `commercial_snapshot` — цены и сроки,
  действовавшие на момент версии.
- Перед экспортом сверяется, что в снимке есть цена и срок (иначе — блок,
  см. «Защитная проверка» ниже).

## Сохранение версий и экспорт PDF

**Политика версий (OQ-03 — решена, реализована):**

- Версия `generated` — на каждую генерацию КП.
- Версия `edited` — на каждое фактическое сохранение правок (кнопка
  «Сохранить изменения»).
- Открытие предпросмотра и экспорт **не создают** новую версию; экспорт
  помечает текущую версию статусом `exported`.
- Прошлые версии неизменяемы; каждая версия хранит свой
  `commercial_snapshot`.

**Экспорт PDF:**

- Предпросмотр показывает выбранную в истории версию, а если выбора нет —
  последнюю версию КП.
- Перед экспортом выполняется защитная проверка (REQ-14, OQ-07):
  - **Структурная сверка** (critical): разделы шаблона и наличие цен/сроков
    в `commercial_snapshot` — при нарушении экспорт **блокируется**;
  - **Эвристика** (warnings): «подозрительные» числа, фразы и обещания —
    выводятся предупреждения, экспорт не блокируется.
  Проверка выполняется в `vetai/services/export_checks.py`.
- PDF строится из той же выбранной версии, что и предпросмотр (ReportLab);
  служебные заметки «Требует уточнения», ключи и персональные данные в PDF
  не попадают (REQ-35).
- **Ограничение проверки:** эвристика возможны ложные срабатывания и
  пропуски; проверка не заменяет ручную вычитку и не является юридической
  экспертизой — перед отправкой КП клиенту проверяйте текст вручную.

## Ограничения MVP

- **Без авторизации и ролей на уровне доступа:** роли — логические
  (OQ-04); любой, у кого есть доступ к машине, работает со всеми разделами.
- **Локальное однопользовательское приложение:** хранилище — один локальный
  файл SQLite; совместная работа и синхронизация не предусмотрены (REQ-39).
- **Один шаблон КП и один прайс** (единый активный шаблон и актуальный прайс).
- **Особенности Streamlit:** состояние сессии хранится в памяти сервера —
  перезапуск процесса сбрасывает UI-состояние (данные в SQLite сохраняются);
  каждое действие вызывает перерисовку страницы; интерфейс привязан к
  Streamlit — отдельного фронтенда и мобильного приложения нет.
- **Работает только локально:** публикация в интернет не выполнялась,
  развёртывания на сервере нет.
- **Не промышленная готовность:** учебный проект; автоматические проверки
  не гарантируют обнаружение всех ошибок в тексте.
- **Импорт Excel — дополнительная возможность** (E-06, сверх ТЗ), а не
  обязательная функция.
- Данные для демонстрации — обезличенные учебные (REQ-38).
