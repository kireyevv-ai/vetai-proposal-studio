# VETAI Proposal Studio — Паспорт проекта

> Документ описывает цель, пользователей, сценарий и границы MVP.
> Источник требований — ТЗ школы. Всё, что не следует из ТЗ школы, помечено как
> **техническое уточнение** или **потенциальное улучшение** и вынесено в
> `OPEN_QUESTIONS.md` и `DELIVERY_PLAN.md`.

Статус документа: синхронизирован с реализацией (коммит `c272c67`, 252 автотеста).
Реализованы все функции обязательного сценария MVP: каркас приложения, база
данных SQLite, форма брифа, настройки (прайс и шаблон КП), генерация черновика
через GigaChat API с программной подстановкой цен и сроков, ручное
редактирование с версионированием, защитная проверка перед экспортом, экспорт
PDF и экран истории КП. Роли остаются логическими (без авторизации, OQ-04);
приложение работает только локально — публикация не выполнялась. Материалы
защиты (видео, кейс, скриншоты) — этап 11 `DELIVERY_PLAN.md`.

---

## 1. Название

- Рабочее название: **VETAI Proposal Studio**
- Тип: учебный проект курса OpenCode — AI-конструктор коммерческих предложений (КП)
  для сервисной компании.

---

## 2. Цель проекта

Сократить подготовку коммерческого предложения **с часов до минут**.

Целевой процесс:

1. Менеджер заполняет бриф.
2. ИИ генерирует черновик КП по утверждённому шаблону.
3. Человек проверяет и редактирует результат.
4. Менеджер выгружает готовое КП в PDF.

Ключевая идея: ИИ ускоряет написание текста, но **коммерческие условия (цены, сроки,
гарантии, обязательства) остаются под контролем доверенных данных и человека**, а не
модели.

---

## 3. Пользователи

Роли описаны в ТЗ школы. На этапе MVP это **логические роли без системы авторизации**
(OQ-04 решён: локальный учебный MVP без авторизации; для публичной эксплуатации с
реальными данными потребуется отдельное решение по доступу — см. раздел 6).

| Роль | Что делает | Источник |
|------|------------|----------|
| **Менеджер** | Заполняет бриф, редактирует КП, выгружает PDF | ТЗ школы |
| **Руководитель** | Определяет шаблон структуры КП и прайс | ТЗ школы |

---

## 4. Обязательный сценарий (happy path)

1. **Заполнение брифа**: клиент, задача, услуги, сроки, бюджет.
2. **Проверка обязательных полей**: незаполненные обязательные поля блокируют генерацию.
3. **Генерация текста** через GigaChat API (выбранный AI-провайдер, OQ-01).
4. **Редактирование результата** менеджером.
5. **Экспорт PDF**, соответствующий окончательно отредактированному КП.
6. **Сохранение истории КП**.

Обработка ошибок на шаге 3 обязательна: таймаут, превышение лимита, пустой ответ —
понятное сообщение пользователю **и сохранение брифа** (данные не теряются).

---

## 5. Обязательные экраны

| Экран | Назначение |
|-------|------------|
| **Бриф** | Ввод клиента, задачи, услуг, сроков, бюджета; проверка обязательных полей |
| **Черновик с редактором** | Показ и ручное редактирование текста КП после генерации |
| **Предпросмотр и PDF** | Предпросмотр итогового КП и экспорт PDF |
| **История КП** | Список сохранённых КП с версией и датой |

---

## 6. Границы MVP

### 6.1 Входит в MVP

- Экраны: Бриф, Черновик с редактором, Предпросмотр и PDF, История КП.
- Один утверждённый шаблон структуры КП и один прайс (управление «руководителем» —
  экран «Настройки»; OQ-02 согласован и реализован).
- Программная подстановка цен из прайса.
- Генерация текста через AI-провайдера **GigaChat API** (OQ-01; интегрирован).
- Валидация структуры и обязательных полей.
- Экспорт PDF (ReportLab) из выбранной версии КП с блокирующей проверкой
  перед экспортом (REQ-14); лог промптов/ответов без персональных данных.
- История КП с версиями и датой (SQLite); экран истории реализован
  (версии `generated` / `edited` / `exported`, прошлые версии неизменяемы).

### 6.2 Явно НЕ входит в MVP (без отдельного согласования)

Согласно правилам проекта — не добавлять бизнес-функции сверх ТЗ школы:

- Авторизация, аутентификация, разграничение прав по ролям.
- CRM, интеграции с почтой, мессенджерами, телефонией.
- Оплата, биллинг, электронная подпись.
- Мультипользовательская работа в реальном времени, совместное редактирование.
- Несколько шаблонов/прайсов, версионирование прайса, скидки, налоги.
- Аналитика, дашборды, отчётность.
- Мобильное приложение, отдельный фронтенд.
- Автоматическая отправка КП клиенту.
- Гарантии юридической корректности/заверений документа.

Любое из перечисленного — только через явное согласование (см. правило 3 в `AGENTS.md`).

## 8. Критерии успеха проекта (учебные)

- Обязательный сценарий проходит от начала до конца на обезличенных данных.
- Ни одна цена в КП не придумана моделью — все берутся из прайса кодом.
- Ошибки API не приводят к потере брифа.
- PDF совпадает с финальной версией текста после редактирования.
- Есть README, тесты и материалы для защиты.
